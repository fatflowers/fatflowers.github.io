02 / SEQUENCE

{{ if $zh }}一次完整运行：输入、处理、输出{{ else }}One complete run: inputs, processing, outputs{{ end }}

  1. 1

    {{ if $zh }}调度与到期查询{{ else }}Schedule and due query{{ end }}

    {{ if $zh }}每 30 分钟触发 collect-due。Worker 根据 enabled、interval_minutes、last_checked_at 返回到期频道；overlap=skip 防止任务重叠。{{ else }}Every 30 minutes, collect-due queries channels due from enabled state, interval, and last check time.{{ end }}

    Input
    catalog + channel cursor
    Output
    GET /v1/channels/due
  2. 2

    {{ if $zh }}固定路由采集{{ else }}Fixed-route collection{{ end }}

    {{ if $zh }}每个频道绑定明确的 collector 与参数模板。MCP 绑定预先验证；主方式失败时按配置尝试 fallback，不在运行时临时选择供应商。{{ else }}Each channel has a fixed collector and template. MCP bindings are pre-verified and configured fallbacks run on failure.{{ end }}

    {{ if $zh }}启用采集器{{ else }}Enabled collectors{{ end }}
    MCP {{ $collectors.Get "mcp" | default 0 }} · RSS {{ $collectors.Get "rss" | default 0 }} · GitHub API {{ $collectors.Get "github_api" | default 0 }} · HTTP {{ $collectors.Get "http" | default 0 }}
    Output
    CollectionPage(items, next_cursor)
  3. 3

    {{ if $zh }}标准化、时间证据与去重{{ else }}Normalize, date evidence, deduplicate{{ end }}

    {{ if $zh }}统一 URL、正文和时间。去重顺序为 channel + external_id → canonical URL → channel + content_hash。目录页只作线索，正文和发布日期未核验前不得进入报告。{{ else }}Normalize URL, body, and time. Dedupe order: channel + external ID, canonical URL, channel + content hash.{{ end }}

    Write
    POST /v1/items/batch
    {{ if $zh }}游标{{ else }}Cursor{{ end }}
    {{ if $zh }}写入成功后才推进{{ else }}advances after successful write{{ end }}
  4. 4

    {{ if $zh }}正文补全与待分析队列{{ else }}Enrichment and pending queue{{ end }}

    {{ if $zh }}研究任务补抓完整正文、最终 URL 和发布日期证据。只允许近 72 小时、正文完整、非 discovery-only、且当前 content revision 尚无分析的条目进入队列。{{ else }}Research resolves full text, final URL, and date evidence. Only recent, complete items without analysis for the current revision enter the queue.{{ end }}

    Read
    GET /v1/items/pending-analysis
    Guard
    content_revision compare-and-swap
  5. 5

    {{ if $zh }}结构化分析{{ else }}Structured analysis{{ end }}

    {{ if $zh }}模型阅读全文并返回严格 JSON：headline、summary、key_change、why_it_matters、importance、confidence、topics、watch_next 和逐事实 evidence。importance（1–5）与 confidence（0–1）仅用于内部排序。{{ else }}The model returns strict JSON for headline, summary, change, impact, scores, topics, next checks, and evidence. Scores are internal ranking signals.{{ end }}

    Validate
    analysis-batch.schema.json
    Write
    POST /v1/analyses/batch
  6. 6

    {{ if $zh }}确定性选稿与生成{{ else }}Deterministic selection and rendering{{ end }}

    {{ if $zh }}按重要度、置信度和时间排序，再按 item ID 与来源 URL 去重；最多 12 条，其中最多 3 条重点。午间版只收 importance ≥ 4；无有效新内容则 skipped。{{ else }}Sort by importance, confidence, and time; dedupe by item ID and source URL. Budget: 12 items, up to 3 leads. Midday requires importance ≥ 4.{{ end }}

    {{ if $zh }}窗口{{ else }}Windows{{ end }}
    08:15 / 12:45 / 18:45 / weekly 7d
    Output
    content/posts/intelligence/*.zh.md
  7. 7

    {{ if $zh }}发布门禁与线上验收{{ else }}Publication gates and live verification{{ end }}

    {{ if $zh }}检查公共来源、证据、敏感信息、Front Matter、Hugo 构建、Git diff 和允许路径；之后提交并推送。Actions 成功后仍会 GET 页面并核对 64 位 artifact 指纹。{{ else }}Public-source, evidence, secret, front matter, Hugo, diff, and path gates run before push. The live page and artifact fingerprint are verified afterward.{{ end }}

    Status
    draft → validating → ready → published
    Failure
    {{ if $zh }}保留草稿并记录 Run / Issue{{ else }}keep draft; record Run / Issue{{ end }}
